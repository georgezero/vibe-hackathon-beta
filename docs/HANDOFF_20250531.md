### Architecture note: server vs client split
Pages that need interactivity but also DB data use a two-file pattern:
- `page.tsx` — async server component, loads from Drizzle, passes serialized data as props
- `ScoringClient.tsx` / `SubmissionClient.tsx` — "use client", handles user interactions, calls API routes

This avoids the `useEffect` fetch-on-mount antipattern while keeping the edit pages as client components.

## Key architectural decisions (permanent)

1. **Server/client split pattern** — pages with DB data + interactivity use two files: `page.tsx` (async server, Drizzle) + `FooClient.tsx` ("use client", fetch API). This avoids `useEffect` data fetching and keeps server-only code out of the client bundle.

2. **Drizzle union type workaround** — `createDb()` returns SQLite | libSQL union, breaking TypeScript inference on `.map()` callbacks. Fix: `import type { InferSelectModel }` and annotate all `.select()` results with explicit types. Required on every file that queries the DB.

3. **Deterministic AI review before LLM** — scoring is evidence-based (file presence, heading detection, length checks). This creates a trust floor: judges can verify every score by looking at the repo. LLM pass comes on top, not instead.

4. **vibe.json as protocol** — `SUBMISSION_SPEC_v1.md` + `vibe.json` + `/api/v1/submissions/from-repo` means the platform has a stable machine-readable contract that agents can consume without reading a human-facing website.

## Session 5 — Final ranking, judge calibration, and exports

### Prompt implemented

Implement Vibe Hackathon final ranking and judge calibration while keeping existing workflows unchanged.

Goals:
- Turn AI review scores, human judge scores, and audience votes into transparent rankings.
- Help admins detect incomplete, missing, or outlier judge reviews.
- Keep audience voting separate from official judging while allowing it to contribute a normalized 10% component.

Requested implementation:
- Final ranking model with `official_score`, `human_average_score`, `ai_reproducibility_score`, `audience_score`, judge completion counts, and `rank_status`.
- Default weighting: human judging 70%, deterministic AI review 20%, normalized audience vote score 10%.
- Admin Rankings tab with rank, project/team, official score, human average, AI review score, votes, judge completion, status, and warning badges.
- Judge calibration view showing assignment/completion counts, average score, standard deviation, average deviation from panel mean, and outlier count.
- Submission detail judging summary with AI breakdown, human scores, audience votes, official score, and formula.
- JSON/CSV exports for submissions, human scores, AI reviews, audience votes, final rankings, and judge calibration.
- README and AGENTS documentation updates.

### New ranking service

**`lib/rankings.ts`** — central derived ranking/calibration service. It computes rankings from current DB rows without overwriting raw records.

Computed ranking fields:
- `officialScore`
- `humanAverageScore`
- `aiReproducibilityScore`
- `aiOverallScore`
- `audienceVotes`
- `audienceScore`
- `judgeCompletionCount`
- `totalAssignedJudges`
- `rankStatus`: `incomplete`, `provisional`, or `final`
- `warnings`
- `humanScores`
- `scoringFormula`

Formula:

```text
official_score = human_average_score * 70% + ai_reproducibility_score * 20% + normalized_audience_score * 10%
```

Details:
- Human rubric scores are converted from the existing 1-10 slider average to a 0-100 score.
- AI reproducibility comes from `ai_reviews.scoring_details.reproducibility_score` when present.
- Older AI review rows fall back to `ai_reviews.generated_score`.
- Audience score is normalized against the highest audience vote total in the event.
- Rankings are derived at request time; raw human scores, AI reviews, and audience votes remain unchanged.

Rank status logic:
- `incomplete`: official score cannot be computed because completed human scores or AI score data is missing.
- `provisional`: score can be computed, but completed judge reviews are fewer than assigned judges.
- `final`: score can be computed and all assigned judges completed reviews.

Warning badges:
- `missing AI review`
- `incomplete judge reviews`
- `judge score outlier`
- `no audience votes`
- `repo validation warning`

Outlier definition:
- A completed human judge score is an outlier when it differs from that submission's completed human panel mean by at least 20 points.

## Session 20 — Audience Voting v1

### What was built

Full identity-based People's Choice voting system. Audience votes are completely separate from official rankings (human judges + deterministic AI review).

### Schema additions

**`events` table** — two new columns:
- `audience_voting_mode` TEXT default `"disabled"` — `"disabled"` | `"human"` (agent/hybrid reserved)
- `audience_identity_method` TEXT default `"anonymous"` — `"badge"` | `"email"` | `"invite_code"` | `"anonymous"`

- Falls through to fingerprint path if `identityMethod === "anonymous"`

**Shared hook**: `hooks/useKeyboardShortcuts.ts`

**Platform convention**: `j = next/forward/down`; `k = previous/back/up`.

Behavior:
- skips shortcuts on touch/mobile devices
- ignores input, textarea, select, and contenteditable targets
- ignores Cmd/Ctrl/Alt modified key chords
- registers and unregisters cleanly

**Help overlay**: `components/ShortcutHelpOverlay.tsx`

Toggled by `?`; closed by `ESC` or backdrop.

**Projects shortcuts**:
- no project card is selected on initial load
- `j` / `k` — move selected project card next/previous
- first `j` selects the first card; first `k` does nothing
- once selected, navigation wraps: `j` from last goes to first, `k` from first goes to last
- `Enter` — open selected project
- `/` — reserved for future search/filter focus; currently no-op

Selected cards get a subtle accent outline and scroll into view. Selection clamps at list boundaries. Clicking a card selects it.

**Project detail shortcuts**:
- `←` / `→` — previous/next project using the same submitted/finalized ordering as `/projects`
- `j` / `k` — next/previous screenshot
- `g` — open GitHub URL in new tab when present
- `d` — open demo URL in new tab when present
- `v` — opens the vote dialog when voting is available; never casts a vote because badge/email entry is still required
- `c` — triggers existing Copy Link behavior
- `p` — back to `/projects`
- `?` — toggle help

**Screenshot/lightbox**:
- `j` / `k` changes selected screenshot on the page
- lightbox keeps `ESC`, `←`, `→`, `j`, and `k`
- project-level previous/next arrows are disabled while lightbox is open

**Roadmap**: command palette remains a future separate slice.
