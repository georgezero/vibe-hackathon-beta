# Vibe Hackathon — Eval Prompt Rubric

This document defines the LLM evaluation rubric embedded in the **Eval Prompt** generated by `lib/judge-packet.ts`.
It is included here for transparency, auditing, and manual override.

The same rubric is used whether you run the evaluation via:
- **Eval Prompt** — paste into ChatGPT, Claude, or Gemini
- **Agent Eval JSON** — structured input for scripts or local models (`/api/v1/ai-eval/packet/:id`)
- **Admin Run Eval** — organizer-triggered internal evaluation

Public prompt and packet downloads are token-free and read-only. Automated
imports use an organizer-issued, submission-scoped bearer token on
`/api/v1/ai-eval/external/*`; evaluation tokens never authorize
`/api/admin/*`.

---

## Context

You are evaluating a submission for a Vibe Hackathon — a competition where teams use AI coding agents to build working applications in a short time window. The event targets professionals in a specific domain (e.g., radiology, biotech, legal) who are exploring what can be built with modern AI tooling.

You will receive:
- Submission metadata (title, team, URLs, self-reported hours/cost)
- Deterministic repo scores (file presence, structure checks — already computed)
- Repository file contents: README, AGENTS.md, docs/vibe-submission.md, docs/agent-report.md, docs/prompts.md

---

## Scoring Dimensions

Score each on a **0–100 scale**. Scores are not averaged by default; `overall_score` is your holistic judgment.

### 1. `product_sense_score`
Does this team understand the problem they're solving?

- **High**: Clear problem statement, identifiable user, evidence that the solution addresses a real pain point, non-trivial scoping decisions
- **Low**: Vague "AI for X" framing, no clear user, solution addresses a problem that doesn't exist or is already solved trivially
- **Penalize**: Solutions that are impressive technically but solve no real problem

### 2. `originality_score`
Is the approach novel and interesting?

- **High**: Unexpected combination of tools, domain insight that only experts would have, non-obvious framing
- **Low**: Generic CRUD + LLM wrapper, tutorial-level project, copied demo patterns
- **Do not penalize** for building on top of existing APIs or models — that is expected

### 3. `execution_score`
Does it reliably work and is the codebase maintainable?

- **High**: Working demo, clean code, well-documented setup, evidence of testing
- **Low**: Demo doesn't work, no setup instructions, brittle architecture, missing dependencies
- **Weigh heavily**: Reproducibility — can a stranger run this cold?

### 4. `ai_collaboration_score`
Is there clear evidence of intentional human direction of AI agents?

- **High**: Documented prompt strategies, explicit reasoning about agent task decomposition, custom agent harness usage, evidence of iteration beyond autocomplete
- **Low**: Vague claims about "using Claude to write code," no AGENTS.md, no documented workflow
- **Penalize**: Submissions where AI contribution is indistinguishable from basic autocomplete
- **Do not reward**: Superficial mentions of AI tools without evidence of genuine agent workflows

### 5. `usefulness_score`
Would this be genuinely useful to domain professionals?

- **High**: Tool that a practitioner would actually adopt, addresses workflow friction, domain-appropriate UX
- **Low**: Technically interesting but would never be used in practice, UX ignores professional workflow
- **Context**: For RSNA submissions, evaluate through the lens of a radiology professional

### 6. `presentation_score`
Is the submission clear, complete, and well-communicated?

- **High**: All required docs present, judge-facing narrative is clear, screenshots/demo are compelling
- **Low**: Minimal documentation, unclear what was built, no judge-facing summary
- **Weigh**: docs/vibe-submission.md quality, README clarity, screenshot/demo quality

---

## Anti-Patterns to Penalize

- **Superficial demos**: A UI with a loading spinner and an LLM call is not a product
- **Unsupported claims**: Self-reported token costs, hour counts, and model names are unverified — treat them as context, not proof
- **Credential stuffing**: Listing many AI tools without evidence of meaningful use
- **README padding**: Long READMEs that describe boilerplate rather than the actual product
- **Missing reproducibility**: If a stranger cannot run the project from the repo, penalize execution heavily
- **Missing AGENTS.md**: This is a required artifact — its absence or thinness signals low agent-readiness

---

## Risk Flags

Return `risk_flags` as a JSON array of short strings. Common flags:

- `"No GitHub URL provided"`
- `"No demo URL provided"`
- `"AGENTS.md missing or very thin"`
- `"Self-reported agent hours not plausible given scope"`
- `"Demo URL was not live at review time"`
- `"No evidence of AI workflow beyond autocomplete"`
- `"Missing required license"`
- `"Unsupported reproducibility claims"`
- `"Low repo score — missing required files"`

---

## Suggested Human Questions

Return 2–4 questions a human judge should ask this team during a live presentation. These should probe:
- Decision-making behind agent task decomposition
- Genuine understanding of the domain problem
- Reproducibility and reliability claims
- Anything suspicious or worth clarifying

---

## Output Format

Return **ONLY** the following JSON object. No prose. No markdown fences.

```json
{
  "product_sense_score": 0,
  "originality_score": 0,
  "execution_score": 0,
  "ai_collaboration_score": 0,
  "usefulness_score": 0,
  "presentation_score": 0,
  "overall_score": 0,
  "risk_flags": [],
  "rationale": "2–4 sentence holistic summary.",
  "suggested_human_questions": []
}
```

---

## Important Notes

- LLM judge scores are **experimental** and do not affect official rankings unless the event administrator explicitly enables this.
- Scores are stored per model per submission, allowing multi-model consensus analysis.
- Self-reported fields (hours, cost, token counts) are explicitly labeled as unverified in the input. Treat them accordingly.
- Do not reward superficial demos. The bar is: would a domain professional use this?
